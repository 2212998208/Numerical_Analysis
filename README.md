# Numerical Analysis Project

This repository provides implementations of common numerical analysis algorithms, including interpolation (Lagrange, Newton, Hermite), root finding (Bisection, Newton-Raphson, Secant, Successive Approximation), and numerical integration (Trapezoidal, Simpson, Double Simpson, RK4-based integrator). The project is organized using C and CMake, with a consistent API design that exposes functionality through structs of function pointers.

## Features
- **Interpolation Algorithms:**
  - Lagrange Polynomial Interpolation
  - Newton Polynomial Interpolation
  - Hermite Interpolation (with derivative information)
- **Non-linear Root Finding:**
  - Bisection Method
  - Newton-Raphson Method
  - Secant Method
  - Successive Approximation (Fixed-point Iteration)
- **Numerical Integration:**
  - Trapezoidal Rule
  - Simpson's Rule (single variable)
  - Double Simpson's Rule (double integrals)
  - Integrator (a standalone RK4 tool with fixed-step and adaptive configurations)

## Building with CMake
CMake is used to build the project, generating multiple executables for the main program and tests.
- **Main Program:** `Numerical_Analysis`, built from `main.c` and all `src/*.c` files.
- **Test Programs:** A separate executable is generated for each module's tests. For example:
  - `Numerical_Analysis_tests_lagrange` is built from `src/lagrange.c` and `tests/test_lagrange.c`.
  - `Numerical_Analysis_tests_integrator` is built from `src/integrator.c` and `tests/test_integrator.c`.
  - Other modules follow the same pattern and are registered with CTest using `enable_testing()` and `add_test()`.

**Build and Run (Windows Command Prompt):**
```
mkdir build
cd build
cmake -S .. -B . -DCMAKE_BUILD_TYPE=Release
cmake --build . --config Release

# Run all tests (optional)
ctest -C Release -V

# Or run a specific test executable
./Numerical_Analysis_tests_lagrange.exe
```
**Note:** If you are using an IDE like MSVC or CLion, it will automatically manage these build targets and tests.

## API Design
- **API Structs:** Each functional module exposes its API through a read-only global instance of a struct. For example:
  - `extern const LagrangeAPI Lagrange;`
  - `extern const IntegratorAPI Integrator;`
- **Function Pointers:** The struct fields are function pointers that point to the actual implementations. The source files initialize these structs with static internal functions.
  - This design hides implementation details, as the internal functions are `static` and only visible within their translation unit.
  - **Initialization:**
    - Positional initialization: `const HermiteAPI Hermite = { hermite_create_interpolator, ... };`
    - Designated initialization (recommended for readability): `const HermiteAPI Hermite = { .hermite_evaluate = hermite_evaluate_impl, ... };`
- **Opaque Handles:** Many modules use opaque handles (`typedef struct Foo* Foo;`) to manage resources, with `create` and `destroy` functions for managing their lifecycle.
- **Error Codes:** Each module defines its own enum for error codes (e.g., `Lagrange_Err`, `Simpson_Err`), with `0` consistently representing success.

## Module APIs and Data Types
This section provides an overview of the APIs from the header files. For detailed parameter descriptions, please refer to the Doxygen comments in the header files and the test cases.

### Integrator (RK4 Integration)
- **Data Types:**
  - `typedef double (*IntegrandFn)(double x, void *user_data);`
  - `typedef enum IntegratorStatus { INTEGRATOR_OK, INTEGRATOR_MAX_STEPS_REACHED } IntegratorStatus;`
  - `typedef struct AdaptiveConfig { double abs_tol; double rel_tol; int max_iterations; } AdaptiveConfig;`
- **API:**
  - `extern const IntegratorAPI Integrator;`
  - **Members:**
    - `double (*rk4_fixed)(IntegrandFn f, void *user, double a, double b, int steps);`
    - `double (*rk4_adaptive)(IntegrandFn f, void *user, double a, double b, AdaptiveConfig cfg, IntegratorStatus *status);`

### Lagrange Interpolation
- **Data Types:**
  - `typedef struct DataSet DataSet;` (opaque dataset)
  - `typedef struct Point { double x; double y; } Point;`
  - `typedef enum Lagrange_Err { LAGRANGE_OK, LAGRANGE_ERR_NOMEM, LAGRANGE_ERR_INVALID, LAGRANGE_ERR_DIVBYZERO } Lagrange_Err;`
- **API:**
  - `extern const LagrangeAPI Lagrange;`
  - **Members:**
    - `double (*lagrange_interpolate)(DataSet *dataset, double x);`
    - `DataSet *(*empty_dataset)(void);`
    - `Lagrange_Err (*create_dataset)(DataSet **dataset, Point *points, size_t size);`
    - `void (*destroy_dataset)(DataSet *dataset);`

### Newton Interpolation
- **Data Types:**
  - `typedef struct NewtonDataSet NewtonDataSet;`
  - `typedef enum Newton_Err { NEWTON_OK, NEWTON_ERR_NOMEM, NEWTON_ERR_INVALID, NEWTON_ERR_DIVBYZERO } Newton_Err;`
- **API:**
  - `extern const NewtonAPI Newton;`
  - **Members:**
    - `Newton_Err (*newton_interpolate)(NewtonDataSet **inNewtonDataSet, DataSet **intData, double x, double *outY);`
    - `Newton_Err (*create_newton_dataset)(NewtonDataSet **outDataset, size_t size);`
    - `Newton_Err (*destroy_dataset)(NewtonDataSet **outDataset);`

### Hermite Interpolation
- **Data Types (Opaque Handles):**
  - `typedef struct HermitePoint* HermitePoint;`
  - `typedef struct HermiteDataset* HermiteDataset;`
  - `typedef struct HermiteInterpolator* HermiteInterpolator;`
  - `typedef enum Hermite_Err { HERMITE_OK, HERMITE_ERR_NOMEM, HERMITE_ERR_INVALID, HERMITE_ERR_DIVBYZERO } Hermite_Err;`
- **API:**
  - `extern const HermiteAPI Hermite;`
  - **Members:**
    - `Hermite_Err (*hermite_create_interpolator)(HermiteDataset*, HermiteInterpolator*);`
    - `Hermite_Err (*hermite_destroy_interpolator)(HermiteInterpolator*);`
    - `HermiteDataset (*create_hermite_dataset)(size_t size, const double *x, const double *y, const double *dy);`
    - `Hermite_Err (*destroy_hermite_dataset)(HermiteDataset*);`
    - `Hermite_Err (*hermite_evaluate)(const HermiteInterpolator*, double x, double *outY, double *outDy);`

### Bisection Method
- **Data Types:**
  - `typedef struct BisectionRange *BisectionRange;`
  - `typedef enum Bisection_Err { BISECTION_OK, BISECTION_ERR_NOMEM, BISECTION_ERR_INVALID, BISECTION_ERR_MAXITER } Bisection_Err;`
- **API:** `extern const BisectionAPI Bisection;`
  - **Members:**
    - `Bisection_Err (*bisection_create)(double (*f)(double), double a, double b, double tol, BisectionRange *outRange, const char *name);`
    - `Bisection_Err (*bisection_solve)(BisectionRange *outRange);`
    - `Bisection_Err (*bisection_destroy)(BisectionRange *outRange);`
    - `double (*bisection_get_midpoint)(const BisectionRange *outRange);`

### Newton-Raphson Method
- **Data Types:**
  - `typedef struct NonLinearRange *NonLinearRange;`
  - `typedef enum NewtonRaphson_Err { NEWTON_RAPHSON_OK, ... } NewtonRaphson_Err;`
- **API:** `extern const NewtonRaphsonAPI NewtonRaphson;`
  - **Members:**
    - `NewtonRaphson_Err (*NonLinearRange_create)(double (*f)(double), double x0, double tol, size_t max_iter, NonLinearRange *outRange, const char *name);`
    - `NewtonRaphson_Err (*NonLinearRange_destroy)(const NonLinearRange *inRange);`
    - `NewtonRaphson_Err (*newton_raphson_solve)(const NonLinearRange *outRange, double *outRoot);`

## Usage Examples
The following pseudo-code demonstrates how to use the APIs. For complete examples, see the `tests/` directory.

- **Lagrange Interpolation:**
  1. Prepare a set of points: `Point pts[] = { {x0,y0}, {x1,y1}, ... };`
  2. Create a dataset: `DataSet *ds = NULL; Lagrange.create_dataset(&ds, pts, n);`
  3. Interpolate: `double y = Lagrange.lagrange_interpolate(ds, xq);`
  4. Clean up: `Lagrange.destroy_dataset(ds);`

- **Adaptive RK4 Integration:**
  1. Define the integrand function: `double f(double x, void *u)`
  2. Configure the integrator: `AdaptiveConfig cfg = {1e-8, 1e-8, 20};`
  3. Integrate: `IntegratorStatus st; double I = Integrator.rk4_adaptive(f, NULL, a, b, cfg, &st);`

- **Newton-Raphson Root Finding:**
  1. Create a range: `NonLinearRange range; NewtonRaphson.NonLinearRange_create(f, x0, tol, iters, &range, "case");`
  2. Solve for the root: `double root; NewtonRaphson.newton_raphson_solve(range, &root);`
  3. Clean up: `NewtonRaphson.NonLinearRange_destroy(range);`

## Testing
- Each module has its own test source file (`tests/test_*.c`) which is compiled with the implementation (`src/*.c`) to create a separate test executable (e.g., `Numerical_Analysis_tests_lagrange.exe`).
- **Running Tests:**
  - Use CTest to run all tests: `ctest -C Debug -V`
  - Or run a specific test executable directly from the command line.
- **Test Style:**
  - Each `tests/test_*.c` file typically contains a `run_all_tests()` function that aggregates all test cases.
  - Tests cover regular, boundary, and exceptional cases (e.g., duplicate nodes, invalid intervals, maximum iterations).

## Development Guidelines
- **Header Comments:** Use Doxygen-style comments in header files to document:
  - Function descriptions, parameters, and return values.
  - Error codes.
  - Ownership (who is responsible for creating/releasing resources).
  - Pre-conditions and post-conditions.
- **Consistent API Design:**
  - Use `extern const <Module>API <ModuleName>;` with internal `static` implementations.
  - Prefer designated initializers for readability: `.field = impl_fn`.
  - Use opaque pointers for resource handles with `create/destroy` functions.
  - Use `0` for success in error codes.
  - Be mindful of naming conflicts between modules (e.g., `Simpson_Err` was defined in both `simpson.h` and `double_simpson.h`).
- **Build and Platform:**
  - On Windows, it is recommended to enable `/W4 /utf-8` (MSVC) or `-Wall -Wextra` (GCC/Clang) and adhere to the `C11` standard.
  - Use `-D_USE_MATH_DEFINES` to make MSVC provide `M_PI` and `M_E`.
